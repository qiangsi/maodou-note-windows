# 毛豆笔记 PRD（简单版）

> 版本：v0.1（简单 PRD）  ·  产品经理：许清楚  ·  日期：2026-11-08
> 产品形态：类 flomo 的极简卡片笔记工具

---

## 1. 产品定位与一句话

- **定位**：类 flomo 的极简卡片笔记工具，主打「随手记录 → #标签组织 → 持续积累」。不强调整理，强调"先记下来"。
- **一句话定位**：**「毛豆笔记 —— 随手记下每一颗灵感豆，用 #标签 自动串起你的思考；本地优先，数据自己说了算。」**
- **差异化（相对 flomo）**：本地优先、断网可用、用用户**自建 WebDAV** 跨端同步、无中心账号绑定（隐私自托管）。

---

## 2. 产品目标（3 个清晰、正交的目标）

| 目标 | 说明 | 可衡量指标 |
|------|------|-----------|
| **G1 极速记录** | 让用户从"想到"到"记下来"的摩擦趋近于零 | 新建一条卡片 ≤ 3 秒完成（无标题、无表单） |
| **G2 标签即结构** | 用 #标签 取代文件夹，零负担组织，回看靠筛选而非搬运 | 单卡片可打多个标签；支持单/多标签筛选 |
| **G3 本地优先 + 自托管同步** | 断网可用，数据掌握在用户手中；通过自有 WebDAV 跨端一致 | 离线可完整 CRUD；WebDAV 同步后双端数据一致、冲突不丢数据 |

---

## 3. 核心用户故事（6 条）

1. 作为**经常冒出灵感的知识工作者**，我想要在任何设备上一句话快速记一条卡片，以便不错过稍纵即逝的想法。
2. 作为**习惯养成者**，我想要每天随手记几条并看到时间流，以便养成"每日思考"的长期积累习惯。
3. 作为**重视隐私的用户**，我想要笔记优先存本地、断网也能用，以便我的数据不依赖任何云服务商的在线状态。
4. 作为**多设备用户**，我想要在安卓手机和 Windows 电脑间通过自己的 WebDAV 同步，以便随时随地续写、不丢数据。
5. 作为**重回顾的人**，我想要按 #标签 筛选某主题的所有卡片，以便快速回看某一类思考脉络。
6. 作为**内容沉淀者**，我想要对卡片做全文搜索，以便在大量积累后仍能精准找回。

---

## 4. 需求池（按优先级分级）

每条需求遵循"作为…我想要…以便…"句式。优先级：**P0**=MVP 必须，**P1**=重要，**P2**=增强。

### P0 — MVP 必须

| 编号 | 需求 |
|------|------|
| P0-1 | 作为用户，我想要在**安卓**和 **Windows** 两端都能新建一条文本卡片，以便随手记录。 |
| P0-2 | 作为用户，我想要给卡片打 **#标签**，以便用标签组织而非文件夹。 |
| P0-3 | 作为用户，我想要首页以**时间倒序**看到全部卡片流，以便回看积累。 |
| P0-4 | 作为用户，我想要按**单个/多个标签**筛选卡片，以便聚焦某主题。 |
| P0-5 | 作为用户，我想要所有数据**本地优先**存储、断网可完整使用，以便离线可用。 |
| P0-6 | 作为用户，我想要配置自己的 **WebDAV** 地址/账号并手动或自动同步，以便跨端一致。 |
| P0-7 | 作为用户，我想要**编辑/删除（软删除）**卡片，以便修正错误。 |
| P0-8 | 作为用户，我想要同步冲突时**数据不丢失**（至少保留双版本），以便安心同步。 |

### P1 — 重要

| 编号 | 需求 |
|------|------|
| P1-1 | 作为用户，我想要**全文搜索**卡片内容与标签，以便快速找回。 |
| P1-2 | 作为用户，我想要看到**标签列表/标签云**及每个标签的卡片数，以便管理结构。 |
| P1-3 | 作为用户，我想要编辑时 `updated_at` 更新但保留 `created_at`，以便追溯。 |
| P1-4 | 作为用户，我想要**导出全部数据**（Markdown/JSON），以便备份与迁移。 |
| P1-5 | 作为用户，我想要**同步状态/上次同步时间**可视化，以便确认同步成功。 |
| P1-6 | 作为用户，我想要新建卡片时界面**无干扰、自动保存**，以便快速记录。 |

### P2 — 增强

| 编号 | 需求 |
|------|------|
| P2-1 | 作为用户，我想要标签支持**嵌套**（#项目/毛豆），以便更细粒度组织。 |
| P2-2 | 作为用户，我想要卡片支持**图片/附件**，以便记录更丰富。 |
| P2-3 | 作为用户，我想要**每日/随机回顾**一张旧卡片，以便"温故"。 |
| P2-4 | 作为用户，我想要**轻量 Markdown**（加粗、列表、链接），以便表达清晰。 |
| P2-5 | 作为用户，我想要**双向链接 [[卡片]]**，以便构建知识网络。 |
| P2-6 | 作为用户，我想要 Windows 端**全局快捷键**快速唤出记录小窗，以便不打断当前工作。 |

## 5. 信息架构 & 关键页面 / 界面描述（文字草图）

**整体信息架构（底部三 Tab / 桌面左栏）**
- 移动端：单栏 + 底部 Tab「首页 / 标签 / 设置」；右上悬浮 **+** 新建。
- 桌面端（Windows）：左侧栏（搜索框、标签树、设置入口）+ 右侧主区卡片流；支持全局快捷键弹出"快速记录"小窗。

### 5.1 卡片流首页（Home）
- 顶栏：搜索图标（右上）、同步状态指示（绿色圆点 + "已同步 2 分钟前"）。
- 主区：**时间倒序卡片瀑布流**。每张卡片显示：正文预览（前 3 行）、标签 chips（#阅读 #灵感）、相对时间（"3 分钟前"）。
- 右上：**悬浮 + 按钮** → 进入新建/编辑页。
- 空状态：居中插画 + "记下今天的第一颗豆 🌱"。

### 5.2 新建 / 编辑卡片页（Composer）
- 顶部无标题栏，直接进入**大输入框**写正文。
- 输入 `#` 触发**标签自动联想**下拉（显示已有标签 + 计数），选中即生成 chip。
- 底部：字数统计 + 保存按钮；**失焦/离开自动保存**（草稿也本地留存）。
- 专注模式：无多余按钮，减少记录摩擦。

### 5.3 标签筛选页（Tags）
- 标签列表：按**使用频次**排序，右侧显示该标签卡片数（#灵感 128）。
- 可选：标签云（字号映射频次）。
- 点击某标签 → 进入该标签的**卡片流筛选视图**（顶部显示"#灵感 · 128 条"，可叠加多选）。

### 5.4 设置 / 同步配置页（Settings）
- **同步方式**：WebDAV 开关。
- **WebDAV 配置**：服务器地址、用户名、密码（密文存储）、测试连接按钮。
- **同步模式**：手动 / 自动（每次改动后）/ 仅 WiFi 自动。
- **同步信息**：上次同步时间、当前状态、冲突日志入口。
- **数据**：导出（Markdown/JSON）、导入。
- **关于**：版本、开源/隐私说明。

## 6. 数据模型初稿（NoteCard）

> 本地存储建议 **SQLite**（双端通用，离线友好，万~十万级足够）。`id` 本地生成并作为同步主键。

### NoteCard（笔记卡片）
| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string (UUID) | 本地生成，全局唯一，作为同步主键 |
| `content` | string | 正文（MVP 纯文本，P2 可轻量 Markdown） |
| `tags` | string[] | #标签 列表（建议去 `#` 存储，如 `["灵感","阅读"]`） |
| `created_at` | datetime (UTC) | 创建时间，**不可变** |
| `updated_at` | datetime (UTC) | 最后更新时间，用于同步冲突判定 |
| `deleted` | boolean | 软删除标记，默认 false（同步时保留以便回收） |
| `device_id` | string | 来源设备标识（冲突/溯源用，P0 可选） |
| `sync_status` | enum | `synced` / `pending` / `conflict`（本地同步状态） |

### SyncMeta（本地同步状态表，P0）
| 字段 | 类型 | 说明 |
|------|------|------|
| `server_base_url` | string | WebDAV 根地址 |
| `last_sync_time` | datetime | 上次成功同步时间 |
| `last_sync_cursor` | string | 增量同步游标（避免全量） |

### （P2 扩展字段，预留）
- `type`: `'text' | 'image'`
- `attachments`: string[]（本地相对路径 / WebDAV 对象 key）
- `links`: string[]（[[卡片 id]] 双向链接）
- `parent_tags`: 嵌套标签路径（#项目/毛豆）

## 7. 待确认问题清单（需与用户 / 架构师对齐）

1. **双端技术栈倾向**：安卓原生（Kotlin）与 Windows 原生（WinUI3 / WPF / .NET MAUI？）是否已有偏好？是否考虑用 **.NET MAUI** 一套代码覆盖安卓 + Windows，以降低双端维护成本？
2. **是否需要账号体系**：产品是否要自建账号/登录，还是**纯本地 + 用户自有 WebDAV（无中心账号）**即可满足？（影响后端与服务边界）
3. **富文本 vs 纯文本**：MVP 正文是**纯文本**还是支持**轻量 Markdown**？图片/附件是否进 MVP，还是放到 P2？
4. **标签嵌套**：早期是否需要**多级标签 #a/b/c**，还是**扁平标签**即可满足？嵌套会显著影响筛选与同步模型。
5. **搜索范围与规模**：全文搜索是否覆盖"标签 + 正文"；数据量目标（万级 / 十万级）是否决定 SQLite 足够，还是需要全文索引方案？
6. **同步冲突策略**：多端同时编辑同一卡片时，采用「**最后写入胜出**」还是「**保留双版本、手动合并**」？是否采用**增量同步**（按 `updated_at` 游标）而非全量上传？
